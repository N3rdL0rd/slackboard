# Building Slackboard

Slackboard is a React Native app built with [Expo](https://expo.dev). The native projects (`android/`, `ios/`) are generated by
`expo prebuild` from `app.json` and the config plugins in `plugins/`. They are git-ignored and never edited by hand: change
`app.json` or a plugin, then rebuild.

App identifier on both platforms: `app.slackboard.client`.

## Prerequisites

- Node.js 22 and npm
- Android: JDK 21 and the Android SDK (`ANDROID_HOME` set)
- iOS: macOS with Xcode

```sh
npm install
npm run typecheck
npm test
```

## Development build

Bluetooth, secure storage and background sync use native modules, so the app does not run in Expo Go. Build and install a
development build once, then load your JavaScript from the Metro dev server.

```sh
scripts/build-android.sh debug       # APK under android/app/build/outputs/apk/debug
npx expo start --dev-client
```

Install the APK on a device or emulator, open it, and connect to the Metro server shown in the terminal. On Android you can
forward the port to a USB-connected device with `adb reverse tcp:8081 tcp:8081`.

The SQLite database needs a native runtime, so the web build is not supported.

## Android release

```sh
scripts/build-android.sh release     # APK under android/app/build/outputs/apk/release
```

A release is signed with the debug key unless you provide your own:

```sh
export SLACKBOARD_KEYSTORE=/path/to/release.jks
export SLACKBOARD_KEYSTORE_PASSWORD=...
export SLACKBOARD_KEY_ALIAS=...
export SLACKBOARD_KEY_PASSWORD=...
```

A debug-signed APK installs and runs but cannot be uploaded to Google Play. Create a key once with:

```sh
keytool -genkeypair -v -keystore release.jks -alias slackboard -keyalg RSA -keysize 2048 -validity 10000
```

Keep it out of the repository (`*.jks` is git-ignored). R8 shrinking is off (`expo-build-properties`) because the Bluetooth
module is loaded by reflection and a shrunk build has not been tested.

## iOS

```sh
npx expo prebuild --platform ios
open ios/Slackboard.xcworkspace       # choose your team under Signing & Capabilities, then Run
```

Installing on a device needs an Apple Developer account and a signing identity. The iOS build has been run on a device.
Nightly Android and iOS builds are linked from the project site.

## Background sync

Background sync is registered through the `expo-background-task` config plugin, so it needs a development or release build and a
rebuild after dependency or `app.json` changes. On Android the system's WorkManager decides when it runs and requires a network
connection. iOS background tasks are opportunistic and are untested here. Foreground sync always works.

## Continuous integration

| Workflow | Runs on | Output |
|---|---|---|
| `ci.yml` | pushes to `main`, pull requests | typecheck and unit tests |
| `android.yml` | nightly at 07:00 UTC, `v*` tags, manual | a release APK (or a debug APK) as a workflow artifact |
| `ios.yml` | nightly at 07:30 UTC, `v*` tags, manual | an unsigned `.ipa` as a workflow artifact |
| `pages.yml` | pushes to `main` that touch `site/`, and after each successful iOS build | the landing page on GitHub Pages, with the latest iOS nightly as `Slackboard.ipa` and the AltStore source `altstore.json` |

For a signed Android release, add repository secrets `ANDROID_KEYSTORE_BASE64` (`base64 -w0 release.jks`),
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` and `ANDROID_KEY_PASSWORD`. Without them the workflow still builds, signed with
the debug key. The iOS build is an unsigned `.ipa`, so it needs no secrets. Install it with AltStore or Sideloadly, which sign it with
your own Apple ID (a free account works, but the app must be refreshed every 7 days), or sign it with your own Apple team. Every build gets a higher version code (Android) or build number (iOS) from the run number.

### Nightly downloads

The site links to the latest nightly artifacts through [nightly.link](https://nightly.link), which serves the newest successful run
without a GitHub login. Install its [GitHub App](https://github.com/apps/nightly-link) on the repository so downloads do not share
the global rate limit. Artifacts are kept for 90 days, so a quiet repository would eventually have nothing to download; the nightly
schedule prevents that. Scheduled runs happen only on the default branch, and GitHub pauses them after 60 days without activity.

AltStore needs a plain `.ipa` URL, which an artifact zip is not, so `pages.yml` also serves the newest iOS build from the site at
`/Slackboard.ipa`, with the source at `/altstore.json`. Add `https://n3rdl0rd.github.io/slackboard/altstore.json` in AltStore. A new
build is offered as an update when its build number changes.

## EAS (optional)

`eas.json` defines `development`, `preview` and `production` profiles for Expo's hosted builds, which can build iOS without a Mac:

```sh
npx eas-cli login
npx eas-cli build --profile preview --platform ios
```

## Testing Bluetooth without a board

`scripts/fake-board.py` pretends to be a board controller: it advertises over Bluetooth, accepts the app's writes, and prints each
decoded message. It needs Linux with BlueZ and `pip install bless`.

```sh
python3 -u scripts/fake-board.py [serial] [api level] [--verbose]
python3 -u scripts/fake-board.py --moonboard --mini
```
